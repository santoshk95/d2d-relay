# Relay UX, journey and wording audit — 10 November 2026

The user asked to deploy everything, make sure all of it reads as if a person wrote it, and review the customer
journeys end to end. The main things people come to Relay for are: **discover what they have, document a process,
build something new, migrate, and fix problems**.

## The front door: from "New dashboard" to what people come for

**Before.** Home's only main action, and the + button on every page, was **New dashboard**. To discover an ERP estate,
document a process, migrate bots or fix a failure, a person had to know which of 56 modules does it. The path was
All modules, then find the card, open the module, pick the work type, press New work and pick the work type again:
five or six steps, plus knowing the catalogue.

**After.**
- Home opens with **What do you want to do?** and six ways in:
  - Discover what you have
  - Document a process
  - Build something new
  - Move to a new platform
  - Fix a problem or make a change
  - Start from an idea (attach anything)
- The + button and the hero button are now **Start new work** and open the same chooser.
- Choosing a kind of work asks **where**: the modules that do that work today, grouped by pillar, with search across
  module names and platforms ("SAP" finds ERP).
  - *Document a process* lists the ways in by what the person has in hand: interviews or a recording, old Visio or
    Word files, documents to check against the real work, an update after a change, requirements, RACI, event logs,
    test plans.
  - *Fix a problem* starts with the screens made for it: Self-healing, AI SDLC and the Service desk.
- Picking a module opens that module's **New work** form with the work type already chosen. Three clicks from Home to
  a filled-in start, with no catalogue knowledge needed.
- **Start from an idea** stays the free-form way in: write it, say it or show it, and Relay suggests where it goes.
- **New dashboard** is still one click away: on the intents line on Home, under *Build something new*, and on the
  Dashboards page.

Each module and work-type pair the chooser offers was checked against the server: 141 pairs; one mismatch
(Ontology has no Fix work) is now sent to its own screen.

**Browser pop-ups replaced.** Eleven questions used the browser's own `prompt()` box: send back, diagnose and close
in Self-healing and AI SDLC; rename, add a section and story line in the Studio; "not helpful" and "send to the
dashboard" in Ask D. They now use the app's dialog (`askText` in `01-core.js`), with a label, a hint, Cancel and a
clear button, keyboard-trapped and named for screen readers. Cancel now means cancel: before, cancelling the
Diagnose box still started a diagnosis.

**Results with no view of their own** showed raw JSON. They now show a table of plain facts, with the rest under
*Technical details*.

## Accessibility

- axe (WCAG 2 A and AA) is clean on the new Home and on the chooser, in light and dark.
- The chooser is a labelled dialog: focus moves in, Tab stays in, Escape closes, and focus returns to the button.
- Tiles are real buttons with names; the phone layout is two columns with titles only.
- The live sweep found no unnamed controls and no sideways scroll on any of the 298 pages.

## Still open: needs a decision or more work

1. **Develop is not live for four modules** that people will expect it from: Apps & products, RPA, Integration &
   APIs, and Cloud & CI/CD. They offer Assess, Fix / change and Run today, so *Build something new* cannot list them. This is already in
   `docs/pending-work.md` §1: Develop there writes to the customer's repository or studio and needs its own design.
2. **Usage & statements is slow** (12.9 s on the live data). It now says what it is doing, but the server walks
   every project folder for each request; caching the folder sizes would fix it.
3. **Admin › Monitoring** still shows rule codes (`daxcheck_offline`, `backup_old`), "build lane" and "Ask D lane",
   and the runner id `claude-code`. These are in Relay Doctor's files (`17-ops.js`, `monitor.py`) and were left
   alone while that session finished.
4. **A few rare server messages are terse**, for example "Unknown version", "Bad request: …" and "Not at the packing
   step (status: …)". They appear only on unusual paths.
5. **The DAX checker was off for about 1.5 hours**, so publishing was blocked. Relay Doctor starts it as routine.

## Only admins see the AI models (the user's decision, 2026-11-10)

The user chose to hide model names from everyone but admins.
- Builders and viewers pick from Relay's own models only: the picker, their default and what the server accepts
  (`main._catalog`, `_model`). Picking another model by the API is refused.
- The top bar, activity, run history, Details, Ask D, Team and Migrate BI name a model only when the person may pick
  it (`modelSeen` / `modelName` in `01-core.js`). A project an admin set to another model shows "Set by an admin".
- `/api/health` names the running model only to admins, or when it is a model the person can pick.
- Admins see everything as before.
- A person who chose their own provider (Codex, Gemini, Antigravity, a LiteLLM route) still sees that choice.
- The API responses that list runs still carry model ids for admin tooling; only the screens hide them.
